<h4 id="1-all-in-llm-vs-code-generation-only">1. All-in-LLM vs Code Generation Only</h4>
<p>생성형 AI를 데이터 분석에 활용하는 방식은 크게 두 가지로 볼 수 있다. 하나는 LLM이 코드 생성부터 실행, 결과 해석까지 모두 수행하는 방식이고, 다른 하나는 LLM이 코드만 생성하고 실제 실행은 로컬 환경에서 하는 방식이다.</p>
<p>빠른 실험이나 EDA에는 All-in-LLM이 편하지만, 재현성이나 보안, 운영까지 고려하면 Code Generation Only 방식이 더 적합할 수 있다. 결국 중요한 것은 AI가 어디까지 대신 할 수 있는지가 아니라, <strong>어디까지 맡길 것인지 판단하는 것</strong>이라고 느꼈다.</p>
<h4 id="2-생성형-ai가-만든-코드를-어디까지-이해해야-할까">2. 생성형 AI가 만든 코드를 어디까지 이해해야 할까?</h4>
<p>AI가 코드를 대신 작성해주는 상황에서 모든 문법을 직접 외울 필요는 없을 것 같다. 하지만 내가 사용하는 코드가 <strong>왜 필요한지, 어떤 결과를 만들고, 잘못됐을 때 어디를 확인해야 하는지</strong>는 이해해야 한다.</p>
<p>특히 요즘 자기소개서에서도 “AI를 활용했다”보다, <strong>어떤 문제에 AI를 활용했고 어떤 판단과 수정 과정을 거쳤는지</strong>를 더 중요하게 보는 것 같다.</p>
<p>그래서 프로젝트를 돌아볼 때 이런 질문을 해보면 좋을 것 같다.</p>
<ul>
<li>AI에게 맡긴 부분과 내가 직접 판단한 부분은 무엇이었나?</li>
<li>AI의 결과를 그대로 사용하지 않았다면 무엇을 수정했나?</li>
<li>그 판단의 근거는 무엇이었나?</li>
<li>AI를 사용해서 실제로 무엇이 개선됐나?</li>
<li>결과가 잘못됐을 때 내가 설명할 수 있는가?</li>
</ul>
<p>결국 중요한 건 AI를 사용했다는 사실이 아니라, <strong>AI의 결과를 검증하고 판단할 수 있었는가</strong>인 것 같다.</p>
<h4 id="3-생성형-ai와-ml의-역할">3. 생성형 AI와 ML의 역할</h4>
<p>생성형 AI와 기존 ML은 서로 대체 관계라기보다 역할이 다르다. ML 모델은 예측을 담당하고, LLM은 사용자의 질문을 이해하고 SQL이나 ML API를 호출해 결과를 설명하는 역할을 할 수 있다.</p>
<p>즉 실제 서비스에서는</p>
<p>사용자 → LLM → 데이터/ML 모델 → 결과 설명</p>
<p>같은 구조가 자연스럽게 사용될 수 있다.</p>
<p>결국 생성형 AI 시대에는 코드를 직접 많이 작성하는 능력보다, <strong>문제를 정의하고 AI를 활용하고 결과를 검증하는 능력</strong>이 더 중요해질 수 있겠다는 생각이 들었다.</p>
